# Управляемый Workflow: Проверенная памятка по авиационной безопасности

## Схема Workflow (5 узлов)

1. **Baseline** → Модель генерирует ответ на наивный запрос → *Критерий:* ответ получен → *Проверка человеком:* оценка полноты по чек-листу (4 критерия).
2. **RCTF-промптинг** → Человек формулирует структурированный запрос → *Критерий:* промпт содержит R, C, T, F + ограничения → *Проверка:* наличие защитных инструкций («не придумывай»).
3. **Генерация v2** → Модель создает улучшенную версию → *Критерий:* ≤200 слов, структура, нет воды → *Проверка:* сравнение v1 vs v2 по рубрике.
4. **Фактчекинг** → Человек ищет ≥2 независимых источника на 3+ утверждения → *Критерий:* все ключевые факты подтверждены → *Проверка:* верификация источников (IATA/FAA/TSA).
5. **Человек-редактор** → Человек добавляет формулы, дисклеймеры, адаптирует тон → *Критерий:* текст готов к публикации → *Проверка:* финальное чтение вслух.

## Контекстная стратегия

| Узел | Что получает модель | Чего НЕ получает |
|------|---------------------|------------------|
| Baseline | Минимальный запрос | Аудиторию, источники, формат |
| RCTF | Роль эксперта IATA, аудиторию, формат | Доступ к внешним источникам |
| Генерация v2 | Полный RCTF-контекст | Право выдумывать лимиты |
| Фактчекинг | Ничего (этап без модели) | — |
| Редактура | Черновик от модели | Знание локальных исключений (Китай, лоукостеры) |

## Правила при неопределённости

- Если точный лимит неизвестен → писать «Требуется уточнение у авиакомпании».
- Если источники противоречат → указывать оба варианта с пометкой «Зависит от перевозчика».
- Если проверка не пройдена → возврат на узел 2 или 4, цикл повторяется.
